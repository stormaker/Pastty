# Pastty 技术选型研究

研究日期：2026-10-24。范围：macOS 本地文字与图片剪贴板历史、低内存、Option+V 历史选择及自动粘贴。本文保留初始设计研究；首版实现进度与实际验证以[首版验收](首版验收.md)为准。当前实现使用Rust核心与轻量Objective-C/AppKit桥，替代最初计划的objc2直接绑定，仍为单进程原生界面。

## 结论

Rust 可行，推荐 Rust 核心 + objc2 直接调用 AppKit 的单进程原生应用：菜单栏入口、NSPanel 浮层、原生列表、SQLite 索引、图片磁盘文件与有限缓存。此方案适合把低常驻内存作为首要目标，但实现和维护 Apple 接口绑定比 Swift/AppKit 更费工。

如果首要目标是较快交付稳定的 macOS 专用工具，Swift + AppKit 同样值得优先考虑。Maccy 自身采用 Swift；换语言并不自动解决缓存过大、图片重复表示、查询一次载入全部历史等问题。没有实测依据证明 Rust 版本一定比设计良好的 Swift 版本省内存。

不推荐把 Tauri/WebView 作为这一极小工具的首选界面。Tauri 使用 Rust 核心和系统 WebView，macOS 为 WKWebView，存在额外 WebView 进程与前后端数据传输；适合重视网页生态或跨平台的项目。这里对内存的判断是架构推断，不能当作具体 MB 的测量结论。[Tauri 进程模型](https://tauri.app/concept/process-model/)

## Maccy 中应借鉴的行为

Maccy 现有交互包含历史搜索、键盘与鼠标选取、可选自动粘贴、无格式粘贴、置顶、删除、暂停记录、应用与类型忽略。用户最新明确只保留文字/图片历史和自动粘贴闭环：搜索、置顶、OCR、同步、文件引用、富文本、复杂设置均不进入实现范围。[官方 README](https://github.com/p0deje/Maccy/blob/master/README.md)

源码的 Clipboard 使用 NSPasteboard.general 与定时器；先比较 changeCount，变化后才读取支持的内容，写回历史项后通过 CGEvent 发送粘贴组合键。类型包括文字、PNG、TIFF、HTML、RTF、文件 URL，并跳过若干临时或保密类型。[Clipboard.swift](https://github.com/p0deje/Maccy/blob/master/Maccy/Clipboard.swift)

以上通用流程链接指向持续变化的 master 分支。另已读取主代理保存的官方2.7.1源码：`Models/HistoryItem.swift` 使用 SwiftData `@Model`，`image` 属性保存 `cachedDecodedImage: NSImage?`，`generateTitle()` 遇图片会启动 `performTextRecognition()`，以 Vision 执行 OCR；同文件也提供 `clearDecodedImageCache()`，所以不能仅看到缓存就推断泄漏。`Storage.swift` 使用 SwiftData ModelContainer，数据库为 Application Support/Maccy/Storage.sqlite。对 Pastty 的直接启示是：用户不需要 OCR，完全省去这条图片解码与识别路径；图片历史用磁盘原数据与按需缩略图即可。本次静态分析不能把先前高内存归因于特定源码缺陷。[2.7.1 HistoryItem](https://github.com/p0deje/Maccy/blob/2.7.1/Maccy/Models/HistoryItem.swift)、[2.7.1 Storage](https://github.com/p0deje/Maccy/blob/2.7.1/Maccy/Storage.swift)

## 用户要求对应的明确行为

| 操作 | Pastty 行为 |
|---|---|
| 在其他应用复制文字或图片 | 有限轮询检测新内容、过滤、去重后保存 |
| Command+V | 保留系统正常粘贴语义，不拦截也不后台抢写剪贴板 |
| Option+V | 弹出历史面板，默认选中最近项目 |
| ↑ / ↓ | 移动选中项，不触发粘贴 |
| Enter 或鼠标单击项目 | 隐藏面板、恢复原应用焦点、写入所选原内容，再自动粘贴 |
| Esc / 点击面板外 | 关闭面板，不改变系统剪贴板 |

“最新内容”应明确为系统当前剪贴板；选中旧历史后，该历史项即成为系统当前内容，下一次 Command+V 粘贴它。这样符合系统和用户刚刚选择的行为，无需接管 Command+V。不要默默在每次 Command+V 时强制改回“最后一次外部复制”的项目。

用户所说“按住 Command+V”按普通快捷键理解；不增加长按阈值或循环切换。Option+V 按下一次弹窗，避免键盘重复事件造成开关抖动。

## Rust 原生方案的组成

| 层 | 建议 | 理由与边界 |
|---|---|---|
| 运行与界面 | Rust + objc2 / objc2-app-kit / objc2-foundation | 使用 NSApplication、NSStatusItem、NSPanel、NSTableView；无需 WebView |
| 系统剪贴板 | NSPasteboard / NSPasteboardItem | 保留项目和类型分组，不把多项目误合并成一种数据 |
| 历史存储 | rusqlite + SQLite | 元数据、文字、索引；限额查询、事务与去重 |
| 图片 | 磁盘保存压缩原数据，ImageIO 生成小缩略图 | 不把所有历史图片解码成 NSImage 常驻 |
| 热键 | 系统全局快捷键注册；局部面板键盘事件 | 优先少监听按键，避免捕获全键盘；具体 Rust 库先验证 macOS 后端与维护情况 |
| 自动粘贴 | NSWorkspace/NSRunningApplication + CoreGraphics CGEvent | 辅助功能授权、焦点恢复、修饰键释放与失败回退 |

objc2 已提供 NSPasteboard.changeCount、读取项目、数据写入以及 NSPanel 等绑定，因此“Rust 只能用网页界面”不成立。AppKit 对象的线程约束、Objective-C 所有权和 autorelease pool 仍必须正确处理；Rust 类型安全不能自动覆盖全部 FFI 使用错误。[objc2 官方项目](https://github.com/madsmtm/objc2)、[NSPasteboard 绑定](https://docs.rs/objc2-app-kit/latest/objc2_app_kit/struct.NSPasteboard.html)、[NSPanel 绑定](https://docs.rs/objc2-app-kit/latest/objc2_app_kit/struct.NSPanel.html)

本机环境已由主代理验证：Swift 6.4 与 Command Line Tools 可用；当前 PATH 中 rustc、cargo 不存在。开发阶段已恢复可用的Rust 1.94.0工具链并完成Release编译；本段前半为研究时环境记录。

## 监听与自动粘贴的难点

### 剪贴板监听

Apple changeCount 随剪贴板所有权变化而递增，可与上次值比较；它不是每一次复制内容的消息队列。[Apple changeCount](https://developer.apple.com/documentation/appkit/nspasteboard/changecount)

建议起始轮询间隔为 300–500 ms，只在计数变化时读取类型和数据。快速连续复制可能在两次采样之间覆盖中间内容，这是有限轮询的边界，不能承诺逐次完整记录。开面板前可补一次检查。休眠暂停、唤醒补查，关闭面板释放图片缓存，避免忙轮询。

读取前后应再次比较 changeCount；读取期间已变化则丢弃混合快照，有限重试下一次变化。来源应用只能作为尽力获得的附加元数据；不能仅凭轮询时的前台应用断言复制来源。

### 自动粘贴

打开面板前记录目标应用 PID；面板需要可接收方向键，同时不能把原编辑位置永久带走。选择后先准备数据并隐藏面板，恢复原应用，等 Option/Command 等物理修饰键释放且目标激活，再注入一次 Cmd+V。必须串行处理一次选择，防止双击或重复键造成多次粘贴。不要对任意全局前台应用盲发按键；原目标退出或激活失败时，仅复制并提示手动粘贴。

CGEvent.post 可向 Quartz 事件流投递事件；跨应用自动粘贴需要处理辅助功能授权。没有授权时保留“选中后复制到剪贴板，用户自行 Command+V”的可用回退，而不是宣称已自动粘贴成功。[Apple CGEvent.post](https://developer.apple.com/documentation/coregraphics/cgevent/post(tap:))、[Maccy 自动粘贴说明](https://github.com/p0deje/Maccy#why-doesnt-it-paste-when-i-select-an-item-in-history)

### Option+V 的边界

部分键盘布局下 Option+字母会输入特殊字符；全局快捷键须正确注册并避免字符同时进入原输入框。macOS 安全输入/密码框可能限制此类快捷键，应保留菜单栏入口作为必要回退，提供一个简洁的快捷键录制设置与冲突提示。Maccy 官方已记录这一类限制；不能保证 Option+V 在所有安全输入场景均可截获，也不应绕过安全输入。[Maccy 安全输入说明](https://github.com/p0deje/Maccy/blob/master/docs/keyboard-shortcut-password-fields.md)

## 低内存的可执行约束

以下是建议的初始产品限额和待验收目标，不是已经达到的性能：

- 默认最多 500 项、30 天、磁盘总量 256 MiB，任一上限触发淘汰；图片单条暂定 16 MiB、文字单条 1 MiB。限额作为后台固定策略，不增加配置页面；超限不存历史但不干扰系统当前剪贴板。
- 内存只保留最近页的 ID、时间、类型、短预览。历史弹窗每页查询约50项，缩略图缓存以字节计限制，例如8 MiB；不要以“100张图片”替代内存字节上限。
- 粘贴时仅加载所选原图。优先保存已有 PNG；只有 TIFF 时保留必要可粘贴表示，缩略图单独存。不要为了生成缩略图先完整解码巨大图片；对宽高和解码预算设限。
- 大图转码、哈希、文件写入使用单个有界工作队列；队列满时合并待检查状态或跳过超限记录，不能无界缓存待处理图片。AppKit 剪贴板访问和 UI 受相应线程约束。
- 大块数据及时释放，循环/工作线程的 Objective-C 临时对象使用明确 autorelease pool。关闭浮窗后清除解码图片和行视图引用。
- SQLite 设置有限 page cache，按需读取；避免 BLOB 与缩略图被一次查询全载入。图片文件名用内容哈希，不使用剪贴板文字作为路径；提交、淘汰和崩溃恢复要处理孤立文件。
- 自身写回的项目标记/计数与内容哈希协同去重；不能只靠“暂停监听100ms”，否则会漏掉用户同期复制。
- 忽略 concealed/transient 等敏感类型；这些规则不能保证识别所有密码。极简版本不做来源应用排除设置、暂停设置、云同步或剪贴板内容日志；菜单栏只需打开历史、设置与退出；设置仅包含显示图标、历史快捷键、登录后自动启动。

推荐验收预算：空闲 physical footprint ≤40 MiB、打开普通历史列表 ≤70 MiB、常态空闲 CPU <0.5%，以该台24 GB M4机器的 Release 构建为准。预算可在最小原型阶段调整。图片捕获/粘贴有合理瞬时峰值，应单独记录；长时间反复操作后必须回落，不能只看第一次启动。

测试要同时记录 RSS 与 physical footprint，并标注采样口径；若采用 Tauri，必须合计应用相关 WebView 进程，不能只报 Rust 主进程。至少覆盖 10,000 次文字复制、1,000 次重复弹窗、数百次图片复制/淘汰与8小时运行，并用真实编辑器、浏览器、微信等目标验证焦点与图片粘贴。所有“低内存达标”必须以实际结果为准。

## 极简管理设置（用户追加确认）

仅三个设置：

1. 显示菜单栏图标：默认开启。关闭后历史快捷键仍可使用；再次打开 Pastty.app 通过已有进程的 reopen 路径显示设置窗口，防止失去入口，不启动第二份监听进程。
2. 历史快捷键：默认 Option+V，可录制更换。先尝试注册新快捷键，成功后注销旧快捷键；冲突或非法组合保留原值，正常 Command+V 不可被占用。
3. 登录后自动启动：初始默认关闭，可切换。通过 Apple SMAppService.mainApp 注册/注销登录项，读取实际 status；needs approval、未注册或失败应正确显示，不仅保存一个布尔值。系统要求确认时，引导到登录项设置。

关闭设置窗口只关闭窗口；退出才停止监听。图标隐藏且自启动时保持后台运行，重新打开应用仍能进入设置。登录后启动不自动弹出设置。菜单栏只提供打开历史、设置、退出，不引入其它功能。

参考：[SMAppService.mainApp](https://developer.apple.com/documentation/servicemanagement/smappservice/mainapp)、[SMAppService.status](https://developer.apple.com/documentation/servicemanagement/smappservice/status-swift.property)。首版已实现这三项设置；本次验证未主动开启当前Mac登录项。

## 开发顺序

1. 系统接口原型：菜单栏、Option+V、NSPanel、文字复制与回贴；先验证授权与焦点，不带完整历史库。
2. 有界存储：SQLite、文字/图片、去重、限额淘汰、缩略图按需加载与删除。
3. 极简闭环与可靠性：方向键与鼠标选择、Enter粘贴、Esc取消、必要授权提示、目标焦点恢复，以及重启后的历史读取；加入仅含三项设置的管理窗口。无需搜索、置顶、OCR、富文本、同步、文件管理或复杂设置。
4. Release 性能与兼容性验收，通过后再签名、打包 .app/.dmg。签名、公证与用户辅助功能授权是不同环节。

最终建议：若决定 Rust，采用原生 AppKit 路线；先通过文字回贴与图片内存峰值原型，再扩展成完整 Pastty。若主要追求尽快获得 macOS 可靠替代品，Swift/AppKit 可减少 FFI 开发成本，同样遵守上述内存与存储约束。
