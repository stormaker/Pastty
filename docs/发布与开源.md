# Pastty 开源与 DMG 发布约定

更新：2026-10-24。正式工作目录：`/Volumes/Docs/IO/Pastty`。当前已有首版应用编译与开发DMG脚本；实际产物与验收结果见[首版验收](首版验收.md)，尚无正式公证发行或GitHub Release。

## 开源仓库

- 项目代码采用MIT许可证；版权声明为Pastty contributors。
- GitHub仓库已指定为[stormaker/Pastty](https://github.com/stormaker/Pastty)，origin为`https://github.com/stormaker/Pastty.git`。初始推送仅包含项目文档与开源基础文件；尚无应用Release。
- 提交应用源码、Cargo.lock、构建/打包脚本、CI、README、LICENSE和第三方通知。保留可复现构建所需版本信息。
- 本机研究原件、REA JSON、Maccy发布包、剪贴板数据库、私钥、证书和生成的安装包不提交Git。公开分析文档保留证据ID/哈希，原始本机证据不承诺在线可取得。
- Bundle ID须在初次正式签名发布前固定，并与GitHub/开发者身份核对，避免后续版本改变辅助功能授权和登录项身份。

## 面向普通用户的安装体验

用户从GitHub Releases下载安装DMG，打开后拖拽Pastty.app到Applications，再启动。用户不需要Rust、Homebrew、Xcode或终端命令。DMG内包括应用和Applications快捷方式，版本、架构和校验和清晰可见。

首版最低系统设计目标为macOS14，正式声明须由实际构建与兼容验证支持。先完成Apple Silicon原生构建；公开覆盖Intel时，补齐x86_64构建及测试。可发布两个架构的DMG，或经验证后合并Universal应用；未验证的架构不标为支持。

首次使用说明只解释自动粘贴所需辅助功能权限，以及系统实际要求的剪贴板访问授权。拒绝辅助功能权限时，选择历史后仍可复制并手动Cmd+V。登录后自启动通过SMAppService，界面反映enabled/requiresApproval等实际状态。

## 构建与发布流水线（待实现）

1. 检查功能与性能验收结果，锁定版本号、commit、Rust工具链和依赖。
2. macOS CI运行必要检查，编译arm64与需要支持的x86_64 Release二进制。命名明确区分开发构建和正式发布构建。
3. 生成标准Pastty.app目录：Info.plist、稳定CFBundleIdentifier、CFBundleShortVersionString、CFBundleVersion、LSUIElement、图标及可执行文件；校验目标架构和最低系统。
4. 使用Developer ID Application签名，启用hardened runtime及必要最小entitlements；在导入后验证签名。签名私钥只存Keychain/临时CI Keychain，证书密码和公证凭据存CI Secrets。
5. 对正确封装的提交物使用notarytool提交并等待结果；成功后为app/staple支持的分发物附加ticket，再生成最终DMG。根据实际打包次序对最终DMG签名、公证并staple；任何外层再打包都要重新验证最终产物。
6. 运行codesign严格验证、stapler validate、Gatekeeper评估与DMG只读挂载检查。验证app和DMG各自状态，不把一次codesign检查当作完整发布验收。
7. 在独立用户/另一台Mac验证下载隔离属性下的拖拽安装、首次运行、权限授权、文字与图片回贴、隐藏图标后重开设置、自启动开关与重启后状态、升级和卸载。
8. 创建版本tag对应的GitHub Release草稿，附DMG、SHA256SUMS、发布说明与兼容范围。正式发布时核对附件属于同一commit，且无研究资料、开发日志或用户内容。

首版已落地构建/验证/DMG脚本与macOS CI workflow；远程CI是否通过以GitHub实际记录为准。正式签名与公证仍需凭据和对应执行证据。

## 公开发布所需外部条件

面向普通用户平顺下载安装的正式版本，计划使用Apple Developer Program下的Developer ID证书和Apple公证。当前未检查是否持有这些凭据，开发可以先进行；缺少证书时产生的本地/未公证构建必须明确标为开发预览，不能声称具备正式分发体验。

GitHub归属已确认为stormaker；代码签名身份、notarytool凭据及需要支持的Intel实机验证，在对应发布步骤前落实。本次没有安装证书、改动系统信任或修改现有项目凭据。

## 验收证据

每次发布记录commit、版本、构建工具链、架构、最低系统、应用/DMG哈希、签名身份、公证结果、Gatekeeper结果、安装验证及资源测量。资源目标见技术选型文档，未实测时不得称为达标。
